# Windows 游戏人物风格转换：交给本机 AI 的开发需求

日期：2026-11-02。状态：**待开发、待实机验收，尚未发布**。

## 先读 r/DLSS5 社区调研补充

用户指定以 r/DLSS5 为重点后，新增了[原帖证据、竞品与验收优先级](REDDIT-DLSS5-NEEDS-20261102.md)。所读讨论更关注原游戏画面的自然/电影化、可复现参数、兼容性、帧率与运动伪影。五种网页风格不是社区需求排名。

先交回本地 RTX Studio 的实际程序/引擎与能力盘点；云端单图版仍按下文独立实现，优先验收保留人物原貌与电影写实。游戏内实时能力需要另做技术验证，不能用这份云端 API 需求替代或宣传为已实现。

## 要做成什么

让用户在 Windows 软件里完成：**拖入一张游戏人物图 → 选风格 → 确认额度 → 生成 → 原图/结果对比 → 保存到本机**。先把单张图片完整做通，再扩展批量。增强/放大作为已有辅助模式保留。

在本仓库现有 `desktop/` Electron 客户端上扩展。当前公开 Windows v0.1.1 只有批量云端增强，不能宣传成人物风格转换版。第一版人物转换复用网站云端服务，不要求本地 RTX、Python、CUDA、WSL 或用户配置开发环境。独立的本地 RTX Studio 不在这一版中合并或改名。

## 第一版必须完成

1. **首页与选图**：默认突出「游戏人物风格转换」，与「图片增强」分开。支持拖放、系统选图、中文/空格路径，JPEG/PNG/WebP。显示原图、尺寸和体积。超过 10 MiB、16,777,216 像素，或任一边小于 16 / 大于 8192 时，提交前说明原因；不偷偷裁剪或压缩后收费。
2. **风格选择**：沿用网页现有五种风格：赛博朋克霓虹、写实奇幻、硬表面科幻、动漫赛璐璐、电影写实。显示可读名称，不要求用户手写英文。提供可选「补充要求」，提交前能查看最终提示词。提示保留脸部特征、发型、服装、动作、镜头构图；这是生成要求，不是效果保证。不要把放大倍数当作风格强度，也不要给现有 API 虚构无效的强度参数。
3. **免登录示例**：可用固定 characterStyle 示例体验并保存结果，明确标注「预设示例 / 来自缓存」。不能把用户自己的文件偷偷传给免费示例接口，不能将缓存结果伪装成刚生成。网络失败、预热和限流要给出可理解提示，有限重试，避免循环请求。
4. **账号与费用**：复用现有网站账号；生成自己的图片前登录、显示余额及本次费用。当前服务每任务预留 1 额度，以服务端为准；提交前说明，完成/失败后刷新余额，不在本地模拟扣费或退款。账号、余额不足、并发任务已满分别提示。Google-only 账号的桌面登录方案若未实现，提供准确提示和网页登录入口，不能索取用户 Google 密码。
5. **生成与任务恢复**：显示上传、排队、处理中、完成、失败，以及真实进度；没有百分比就显示阶段。双击按钮、网络重试、重开软件不能重复提交或重复扣费。保存 jobId、幂等键和任务设置；断线/重启后先恢复查询已有任务。`SUBMISSION_UNCERTAIN` 继续核对原任务，不新建任务。改变风格/提示词/图片才属于新任务，须重新确认费用。超时不等于失败，不表示服务器已停止或退款。
6. **前后对比**：原图与结果并排或拖动对比，可放大检查脸、手、头发、衣服和武器。结果可能修改身份特征，要允许用户指出问题并修改要求后重新确认生成，不显示「100% 保持人物一致」。
7. **保存**：结果通过账号鉴权下载到用户选定目录；不覆盖原图、同名文件不静默覆盖。中文/空格路径正确。图片扩展名匹配实际内容；可另存 JSON 记录风格、最终提示词、jobId、输入/输出尺寸、时间和客户端版本，不包含 token/密码/带签名的临时 URL。任务完成而保存失败时，可重试下载和保存，不能重新生成收费。
8. **Windows 使用体验**：正常 x64 安装包、开始菜单入口、中文/英文界面。用户不需要开终端或 WSL。保留已有增强功能；首版不加视频、游戏注入、实时帧生成、多模型平台或驱动替换。不要升级任何服务套餐。

## API 接线要点（已按网站源码核对）

基础地址 `https://www.dlss5nvidia.com`。自有图片请求在主进程使用用户 `Authorization: Bearer <ID token>`；不要将 token 发给 renderer 或写进日志，不需要新的服务商密钥。

1. 沿用现有登录和 `POST /api/me/bootstrap` 初始化账号 / 读取余额。
2. `POST /api/image-edit/upload`：`fileName, contentType, size, width, height, model: "flux-klein"`，取得 `upload_url, headers, file_id`；再 PUT 图片字节到签名上传地址。**上传票据的 fileName 目前只允许 ASCII 字母数字、空格、点、下划线、连字符，长度 1–180。** 中文原路径仍保留在本机，票据名可用 `character-<random>.png`，避免中文路径导致 API 400。鉴权头只发官网 API；PUT 签名 URL 只带票据返回的头，不转发账号 token。
3. `POST /api/image-edit/jobs`，header `Idempotency-Key`（非空、最多 128 字符），正文示例：

```json
{
  "mode": "edit",
  "image_ids": ["<file_id>"],
  "prompt": "<所选风格 prompt + 保留项 + 用户补充要求；总长不超过 4000>",
  "source_width": 1440,
  "source_height": 778,
  "seed": 42,
  "num_inference_steps": 4,
  "output_format": "webp"
}
```

UI 的 workflow 名为 `game-character-style`，但 API **mode 必须是 `edit`**，不能发明 `mode=game-character-style`。现有网页五个 preset 是 prompt 配方，不是新的服务端 preset 参数。首版仅传一张图；参考风格图作为后续扩展，避免错接第二张图的含义。

服务端按原图比例计算输出：长边最多 1536、尺寸四舍五入到 16 的倍数，不放大小图；以 API 实际返回尺寸为准。不能承诺 4K、固定精确比例或实时。`mode=enhance` 的 2x/4x 控制只留在增强模式。

4. 用 jobId 请求 `GET /api/image-edit/jobs/{jobId}`；终态 `SUCCEEDED` / `FAILED`，同时处理 `QUEUED`、`RUNNING`、`SUBMISSION_UNCERTAIN`。保持最多一个轮询请求在途、后台退避，关窗后不做忙轮询。
5. 成功后 `GET /api/image-edit/results/{jobId}` 鉴权下载。已完成任务的保存失败只重试下载。
6. 免费样例：无登录 `POST /api/image-edit/samples`，JSON `{"sample":"characterStyle"}`。HTTP 200 的 `result` 是结果地址，返回 `cached` / `extension` 等信息；202 `WARMING` 时退避并设总等待上限（可沿用网页 90 秒）。固定原图和结果地址见清单；429 不绕过。样例渲染尺寸独立于自有图片，不能把样例几何当作上传 API 的规格。

## 防重复与可靠性要求

幂等语义至少覆盖账号、图片内容、风格清单 revision、风格 ID、最终 prompt、seed、输出设置。提交意图先落盘，再发请求；保存后的 jobId 要能跨进程恢复。相同任务的重试复用原幂等键。跨账号不复用任务或结果。新任务与恢复旧任务在界面上区分。

不要依赖文件名判断风格任务已完成：同一图不同风格应各自保留结果；重复任务可以跳过，但要说明使用了哪次结果。

- 自动化使用本地 mock 验证请求、幂等、恢复、保存；不能给测试自动注册真实账号或无限跑付费云任务。实机云测试先使用用户提供的测试账号，报计划消耗，再记录实际消耗；不要把密码或 token 回传。
